# 管家婆账单导入：Dify 工作流怎么搭、怎么接到系统

智能体**只负责从文件里抽出流水 JSON**，不直接写 MySQL。
入库、家庭隔离、金额/日期/分类校验仍走本系统的 `RecordService`。

解析结果会先出现在「文件导入」页的待确认区，勾选后再入库。
风景照、成绩单、合同等无关文件会被标出原因，不会写入账本。

云主机上「系统已经在跑、只要补文件导入」请先看同目录的 [`云主机迁移.md`](./云主机迁移.md)。

---

## 哪些文件还要走智能体

| 文件 | 是否调用 Dify |
| --- | --- |
| 带表头的 Excel / CSV（日期或收支 + 金额，列名不限微信/支付宝） | **不走**，本机按列语义抽取 |
| 微信「交易明细证明」PDF（有文字层） | **不走**，本机按折行拼流水 |
| 支付宝「交易流水证明」PDF（有文字层） | **不走**，本机按表格抽流水 |
| 普通文字 PDF，本机能认出账单表 | **不走** |
| 列名是黑话、但单元格里仍有日期和金额 | **尽量不走**：本机会从数据行反推列；英文日期、`12.34元（优惠后）`、Dr/Cr 也能认 |
| 完全认不出列、也扫不到「日期+金额」的怪表 | **会走 Dify**：把用户上传的原文件交给工作流，先走文档提取器，再由 `qwen3.8-max` 抽 JSON |
| 小票照片、扫描件 PDF（几乎没有文字层） | **会走 Dify**：文档提取器读不出字时，走「大模型文档解析」（PaddleOCR-VL-1.6），再由 `qwen3.8-max` 抽 JSON |

微信 / 支付宝官方表和证明 PDF **不走智能体**，本机一秒内能抽出。
本机认得出的怪表也不走模型。只有本机完全抽不出时，才把**原文件**交给 Dify（文档提取器 / PaddleOCR-VL）。不要在本机另装 Tesseract。没配任何 Key 时，Excel / 微信证明 PDF / 支付宝流水证明 PDF 仍然能导入。

入库时可选「直接入库」或「合并后入库」。合并会与账本、本次其他文件比对，同一天同金额同商家只留一份。

## 1. 在机器上安装 Dify

最低大约 **2 核 CPU、4 GB 内存**。需要 Docker 与 Docker Compose 2.24+。

不要和管家婆抢 80 端口。管家婆默认 `8080`；Dify 官方默认也占 `80`。云主机上建议把 Dify 改到 `8088`。

本机 Docker 必须给插件一个能下载上传文件的地址，否则图片走 PaddleOCR 会报 `FILES_URL` / 相对路径错误。在 Dify 的 `docker/.env` 里设置：

```bash
FILES_URL=http://127.0.0.1
INTERNAL_FILES_URL=http://api:5001
```

然后 `docker compose restart api worker plugin_daemon`。CSV/Excel 只走文档提取器，不依赖这两项。

```bash
# 装 Docker（Debian / Ubuntu 示例）
# curl -fsSL https://get.docker.com | sh
# sudo usermod -aG docker $USER   # 重新登录后生效

sudo apt-get update
sudo apt-get install -y git curl jq

git clone --branch "$(curl -s https://api.github.com/repos/langgenius/dify/releases/latest | jq -r .tag_name)" https://github.com/langgenius/dify.git
cd dify/docker
cp .env.example .env
```

若 `jq` 取不到版本号，到 https://github.com/langgenius/dify/releases 看最新 tag，再：

```bash
git clone --branch 1.11.2 https://github.com/langgenius/dify.git
```

编辑 `dify/docker/.env`，避免和管家婆或其它网站抢端口：

```bash
EXPOSE_NGINX_PORT=8088
EXPOSE_NGINX_SSL_PORT=8443
```

启动：

```bash
docker compose up -d
docker compose ps
```

浏览器打开（本机用 `127.0.0.1`，云主机用公网 IP 或域名）：

```
http://<主机>:8088/install
```

按页面创建管理员账号，然后登录工作室。官方说明：https://docs.dify.ai/en/self-host/quick-start/docker-compose

管家婆和 Dify 在同一台机器时，后端应访问：

```
http://127.0.0.1:8088/v1
```

不要用浏览器里的 `/app/...` 地址当 API。

## 2. 配置大模型（必须先做）

工作室 → 右上角头像 → **设置 → 模型供应商**。

本仓库导出的 DSL 用的是通义千问（`langgenius/tongyi`，模型名 `qwen3.8-max`）。云主机上二选一：

1. **继续用通义**：在插件市场安装「通义千问 / Tongyi」，填阿里云 DashScope API Key。
2. **换成别的**：导入 DSL 后打开「账单解析」LLM 节点，改成已配置的文本模型。

通义节点的 `temperature` **必须 ≥ 0.6**，否则该供应商会拒请求。

图片小票走工作流里的 PaddleOCR 节点，见第 3 节。表格文本仍可配 `DASHSCOPE_API_KEY` 直连通义（见第 5 节）。

## 3. 导入「管家婆账单导入」工作流

不要新建 Chatflow / 对话型应用，必须是 **工作流 (workflow)**。

1. 打开 Dify 工作室。
2. 「创建应用」旁的菜单 → **导入 DSL**。
3. 上传本目录的 `管家婆账单导入.yml`。
4. 若提示版本不一致，按页面确认导入。
5. 打开编排，核对流：`用户输入` → `文档提取` → `是否抽出文字` →（有字）`汇总文件文字` → `账单解析`（LLM）→ `结束`；没字则先走 `大模型文档解析` 再汇总。
6. 点右上角 **发布**。

开始节点三个变量必须和管家婆后端一致（DSL 里已写好）：

| 变量 | 类型 | 说明 |
| --- | --- | --- |
| `bill_file` | **File**（单文件，不是 Array[File] / `files`） | 图片或 PDF，可选 |
| `text_content` | 段落文本 | Excel/CSV 抽出来的表格，可选 |
| `categories` | 段落文本 | 本家庭末级分类名单 |

「账单解析」是 **LLM 节点**（不要再用经典 Agent 挂 file 工具，Dify 1.15 会直接报 `file type parameter not supported in agent`）：

- 模型：`qwen3.8-max`，`temperature` ≥ 0.6
- 上游：文档提取器读 CSV/Excel/PDF/Word；读不出字再走 PaddleOCR-VL-1.6
- 结束节点输出变量名：`result`（取 LLM 的 `text`）

### 3.1 图片 / 扫描件走 PaddleOCR

小票、扫描件用官方插件 **PaddleOCR**（`langgenius/paddleocr`）的「大模型文档解析」，模型固定 `PaddleOCR-VL-1.6`。这就是百度星河社区那套异步 OCR（`paddleocr.aistudio-app.com`）。

配置：

1. 插件市场安装 PaddleOCR。
2. 工具授权里填 **星河社区访问令牌**（[获取](https://aistudio.baidu.com/account/accessToken)）。令牌只放 Dify 凭据，不要写进仓库或 DSL。
3. 工作流里「大模型文档解析」节点的文件入参绑 `bill_file`。
4. 重新 **发布**。

不要在本机另写 OCR，也不要把 Token 提交到 git。

导入后如果模型是空的或报插件缺失，按第 2 节装供应商，再在节点里选模型，然后重新发布。

## 4. 手工搭一遍（没有 DSL 时）

1. 工作室 → 创建应用 → **工作流**，名称「管家婆账单导入」。
2. 开始节点加三个变量：`bill_file`（File，image+document）、`text_content`、`categories`。
3. 主工作流加 **文档提取器**，文件选 `bill_file`；提取失败时用默认空文字。
4. 提取结果为空时接到 PaddleOCR「大模型文档解析」，否则直接汇总文字。
5. 加 **LLM** 节点，模型选 `qwen3.8-max`，`temperature` ≥ 0.6，提示词用下面第 6 节，并放入 `categories`、`text_content` 和汇总后的文件文字。
6. 结束节点增加输出 `result`，值为 LLM 的 `text`。
7. 发布。

## 5. 复制 API Key，接到管家婆

表格和小票优先直连通义，失败再回退 Dify。两套 Key **只放环境变量**，不要写入 `application.yml`，不要提交 git。

### 5.1 通义直连（推荐，表格更快）

阿里云百炼 / DashScope 控制台创建 API Key，启动前导出：

```bash
export DASHSCOPE_API_KEY=sk-xxxxxxxx
# 可选：更快可改 qwen-turbo；默认 qwen-plus / qwen-vl-plus
# export QWEN_TEXT_MODEL=qwen-plus
# export QWEN_VISION_MODEL=qwen-vl-plus
```

### 5.2 Dify（图片 / 扫描件，以及没配通义时）

1. 打开该应用的 **访问 API**（`/app/<id>/develop`）。
2. 创建密钥，得到 `app-` 开头的一串。

管家婆启动示例（Dify 在本机 8088）：

```bash
export DASHSCOPE_API_KEY=sk-xxxxxxxx
export DIFY_BASE_URL=http://127.0.0.1:8088/v1
export DIFY_API_KEY=app-xxxxxxxx
export DIFY_MODE=workflow
java -jar 运行包/gjp-server-1.0.0.jar
```

本机 Dify 若仍映射在 80，则 `DIFY_BASE_URL=http://127.0.0.1/v1`。

改 Key 或地址后必须重启管家婆。可用环境变量模板：`env.example`。

已发布的旧工作流若「账单解析」还是经典 Agent 并挂着 file 工具，请重导本目录 DSL：改成 **文档提取 →（空则 PaddleOCR）→ LLM**，然后重新发布。经典 Agent 在 Dify 1.15 不能带必填 file 工具参数。

## 6. 系统提示词

```
你是「管家婆」家庭收支管理系统的账单解析智能体。
上游 Dify 文档提取器或市场读文件工具已经把文件读成文字。你只根据文字抽出收支流水，不要要求看图。
文件里可能有几十上百笔，必须尽量逐笔抽取，不要合并、不要只给汇总。

只输出一个 JSON 对象，不要 Markdown，不要解释。格式：
{
  "relevant": true,
  "reason": "",
  "records": [
    {
      "type": 2,
      "amount": 28.50,
      "recordDate": "2026-08-01",
      "categoryName": "正餐",
      "merchant": "海底捞",
      "area": "",
      "payMethod": "微信",
      "isGift": 0,
      "remark": ""
    }
  ]
}

规则：
1. type：1=收入，2=支出。看不出时按支出。
2. amount 必须是大于 0 的数字。
3. recordDate 用 YYYY-MM-DD。没有年份时用当年；完全没有日期则跳过该行。
4. categoryName 必须从用户提供的分类名单里选一个最接近的末级分类，不要自造分类。
5. payMethod 只能是：现金 / 微信 / 支付宝 / 银行卡 / 其他，不确定就留空。
6. isGift：礼金、红包、随份子、请客送礼为 1，否则 0。
7. 如果文件与家庭账单无关（风景照、论文、合同、纯文字小说、空白表等）：
   返回 {"relevant": false, "reason": "一句话说明为什么不是账单", "records": []}
8. 能看懂一部分就抽一部分；完全看不懂按无关文件处理。
9. 商家、片区、备注、分类名一律用中文原文，禁止翻译成英文。categoryName 必须是分类名单里的中文末级名。
```

## 8. 试跑

本目录样例：

- `示例账单.csv`：多笔混合收支，未配置 Key 也能抽出
- `无关文件.csv`：成绩表，应被标成无关、不入库

前端入口：左侧「文件导入」，或右下角悬浮球 →「文件上传」。一次最多选 **10** 个文件（单文件 ≤ 12MB，整次 ≤ 120MB），文件对话框里按住 Command / Ctrl 可连选。

图片识别：随便拍一张小票，确认能抽出金额和商家。微信 / 支付宝整月 Excel、CSV，「交易明细证明」或「交易流水证明」PDF 应在数秒内完成本机抽取，不应再出现 `request timed out`。
