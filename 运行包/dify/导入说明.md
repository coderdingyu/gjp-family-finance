# 管家婆账单导入：Dify 工作流怎么搭、怎么接到系统

智能体**只负责从文件里抽出流水 JSON**，不直接写 MySQL。
入库、家庭隔离、金额/日期/分类校验仍走本系统的 `RecordService`。

解析结果会先出现在「文件导入」页的待确认区，勾选后再入库。
风景照、成绩单、合同等无关文件会被标出原因，不会写入账本。

云主机上「系统已经在跑、只要补文件导入」请先看同目录的 [`云主机迁移.md`](./云主机迁移.md)。

---

## 哪些文件还要走智能体

| 文件 | 是否调用 Dify |
| --- | --- |
| 微信 / 支付宝官方导出的 Excel、CSV（能认出日期、金额、收/支） | **不走**，本机按表头抽取 |
| 微信「交易明细证明」PDF（有文字层） | **不走**，本机按折行拼流水 |
| 普通文字 PDF，本机能认出账单表 | **不走** |
| 表头认不出的怪表格 | **会走**，切成小块再问工作流 |
| 小票照片、扫描件 PDF（几乎没有文字层） | **会走**，必须视觉模型 |

所以配好 Dify 主要是为了**图片和扫描件**。没配 Key 时，Excel / 微信证明 PDF 仍然能导入。

入库时可选「直接入库」或「合并后入库」。合并会与账本、本次其他文件比对，同一天同金额同商家只留一份。

## 1. 在机器上安装 Dify

最低大约 **2 核 CPU、4 GB 内存**。需要 Docker 与 Docker Compose 2.24+。

不要和管家婆抢 80 端口。管家婆默认 `8080`；Dify 官方默认也占 `80`。云主机上建议把 Dify 改到 `8088`。

```bash
# 装 Docker（Debian / Ubuntu 示例）
# curl -fsSL https://get.docker.com | sh
# sudo usermod -aG docker $USER   # 重新登录后生效

sudo apt-get update
sudo apt-get install -y git curl jq

git clone --branch "$(curl -s https://api.github.com/repos/langgenius/dify/releases/latest | jq -r .tag_name)" https://github.com/langgenius/dify.git
cd dify/docker
cp .env.example .env
```

若 `jq` 取不到版本号，到 https://github.com/langgenius/dify/releases 看最新 tag，再：

```bash
git clone --branch 1.11.2 https://github.com/langgenius/dify.git
```

编辑 `dify/docker/.env`，避免和管家婆或其它网站抢端口：

```bash
EXPOSE_NGINX_PORT=8088
EXPOSE_NGINX_SSL_PORT=8443
```

启动：

```bash
docker compose up -d
docker compose ps
```

浏览器打开（本机用 `127.0.0.1`，云主机用公网 IP 或域名）：

```
http://<主机>:8088/install
```

按页面创建管理员账号，然后登录工作室。官方说明：https://docs.dify.ai/en/self-host/quick-start/docker-compose

管家婆和 Dify 在同一台机器时，后端应访问：

```
http://127.0.0.1:8088/v1
```

不要用浏览器里的 `/app/...` 地址当 API。

## 2. 配置大模型（必须先做）

工作室 → 右上角头像 → **设置 → 模型供应商**。

本仓库导出的 DSL 用的是通义千问（`langgenius/tongyi`，模型名 `qwen3.8-max`）。云主机上二选一：

1. **继续用通义**：在插件市场安装「通义千问 / Tongyi」，填阿里云 DashScope API Key，并保证有一个**支持视觉**的模型（图片小票需要 vision）。
2. **换成别的**：导入 DSL 后打开「账单解析」节点，改成你已配置且支持视觉的模型。

通义节点的 `temperature` **必须 ≥ 0.6**，否则该供应商会拒请求。

## 3. 导入「管家婆账单导入」工作流

不要新建 Chatflow / 对话型应用，必须是 **工作流 (workflow)**。

1. 打开 Dify 工作室。
2. 「创建应用」旁的菜单 → **导入 DSL**。
3. 上传本目录的 `管家婆账单导入.yml`。
4. 若提示版本不一致，按页面确认导入。
5. 打开编排，核对三个节点：`用户输入` → `账单解析` → `结束`。
6. 点右上角 **发布**。

开始节点三个变量必须和管家婆后端一致（DSL 里已写好）：

| 变量 | 类型 | 说明 |
| --- | --- | --- |
| `bill_file` | **File**（单文件，不是 Array[File] / `files`） | 图片或 PDF，可选 |
| `text_content` | 段落文本 | Excel/CSV 抽出来的表格，可选 |
| `categories` | 段落文本 | 本家庭末级分类名单 |

「账单解析」节点：

- 视觉：**开启**，变量选 `bill_file`
- 结束节点输出变量名：`result`（取 LLM 的 `text`）

导入后如果模型是空的或报插件缺失，按第 2 节装供应商，再在节点里选模型，然后重新发布。

## 4. 手工搭一遍（没有 DSL 时）

1. 工作室 → 创建应用 → **工作流**，名称「管家婆账单导入」。
2. 开始节点加三个变量：`bill_file`（File，image+document）、`text_content`、`categories`。
3. 加 LLM 节点，视觉开，绑 `bill_file`，`temperature` ≥ 0.6。
4. 系统提示词用下面第 6 节全文；用户提示词：

```
可选末级分类名单：
{{categories}}

以下是从表格文件抽出的文本（可能为空，此时请识别附件账单）：
{{text_content}}

请识别附件或上述文本中的账单。如果内容与家庭收支无关，按无关文件返回。
```

5. 结束节点增加输出 `result`，值为 LLM 的文本。
6. 发布。

## 5. 复制 API Key，接到管家婆

1. 打开该应用的 **访问 API**（`/app/<id>/develop`）。
2. 创建密钥，得到 `app-` 开头的一串。
3. **只放环境变量**，不要写入 `application.yml`，不要提交 git。

管家婆启动示例（Dify 在本机 8088）：

```bash
export DIFY_BASE_URL=http://127.0.0.1:8088/v1
export DIFY_API_KEY=app-xxxxxxxx
export DIFY_MODE=workflow
java -jar 运行包/gjp-server-1.0.0.jar
```

本机 Dify 若仍映射在 80，则 `DIFY_BASE_URL=http://127.0.0.1/v1`。

改 Key 或地址后必须重启管家婆。可用环境变量模板：`env.example`。

## 6. 系统提示词

```
你是「管家婆」家庭收支管理系统的账单解析智能体。
用户会给你一张图片、一份 PDF，或一段从 Excel/CSV 抽出来的表格文本。
你的任务是抽出其中的收支流水。文件里可能有几十上百笔，必须尽量逐笔抽取，不要合并、不要只给汇总。

只输出一个 JSON 对象，不要 Markdown，不要解释。格式：
{
  "relevant": true,
  "reason": "",
  "records": [
    {
      "type": 2,
      "amount": 28.50,
      "recordDate": "2026-08-01",
      "categoryName": "正餐",
      "merchant": "海底捞",
      "area": "",
      "payMethod": "微信",
      "isGift": 0,
      "remark": ""
    }
  ]
}

规则：
1. type：1=收入，2=支出。看不出时按支出。
2. amount 必须是大于 0 的数字。
3. recordDate 用 YYYY-MM-DD。没有年份时用当年；完全没有日期则跳过该行。
4. categoryName 必须从用户提供的分类名单里选一个最接近的末级分类，不要自造分类。
5. payMethod 只能是：现金 / 微信 / 支付宝 / 银行卡 / 其他，不确定就留空。
6. isGift：礼金、红包、随份子、请客送礼为 1，否则 0。
7. 如果文件与家庭账单无关（风景照、论文、合同、纯文字小说、空白表等）：
   返回 {"relevant": false, "reason": "一句话说明为什么不是账单", "records": []}
8. 能看懂一部分就抽一部分；完全看不懂按无关文件处理。
9. 商家、片区、备注、分类名一律用中文原文，禁止翻译成英文。categoryName 必须是分类名单里的中文末级名。
```

## 7. 已有数据库升级

**不要**对已有库再执行整份 `schema.sql`（会 DROP 库）。只补导入表：

```bash
mysql -u root < 运行包/patch_import.sql
# Docker 里的 MySQL：
# docker exec -i gjp-mysql mysql -u root < 运行包/patch_import.sql
```

新库可以直接用更新后的 `运行包/schema.sql`。

## 8. 试跑

本目录样例：

- `示例账单.csv`：多笔混合收支，未配置 Key 也能抽出
- `无关文件.csv`：成绩表，应被标成无关、不入库

前端入口：左侧「文件导入」，或右下角悬浮球 →「文件上传」。

图片识别：随便拍一张小票，确认能抽出金额和商家。微信整月 Excel / 「交易明细证明」PDF 应在数秒内完成本机抽取，不应再出现 `request timed out`。
