# 数据库安装与升级

本系统用 **MyBatis + 手写 SQL**，没有 JPA `ddl-auto`。表结构有两套入口，用途不同，**不要混用**。

## 空机器 / 课程一键演示（会清空库）

`运行包/schema.sql`（与 `源码/server/src/main/resources/db/schema.sql` 同步）是一次性引导脚本：

```sql
DROP DATABASE IF EXISTS gjp;
CREATE DATABASE gjp ...
```

只允许在**空机器、确认没有需要保留的数据**时执行：

```bash
mysql -u root < 运行包/schema.sql
mysql -u root < 运行包/data.sql
```

`源码/启动.sh` 也是「库里还没有 `t_record` 才跑 schema.sql」。

**永远不要对已经有流水、账号、导入任务的库执行 `schema.sql`。** 它会 `DROP DATABASE`，演示数据与真实记账会一起没。

## 已有库升级（Flyway，只加不删）

从本版本起，应用启动时启用 Flyway：

- 脚本目录（源码真相）：`源码/server/src/main/resources/db/migration/`
- 运行包副本：`运行包/migrate/`（与上面同步，便于手工对照）
- `spring.flyway.enabled=true`
- `spring.flyway.baseline-on-migrate=true`
- `spring.flyway.baseline-version=1`

已有 `gjp` 库（当前线上/演示库）第一次启动时：

1. Flyway 发现没有 `flyway_schema_history`，把现有结构标成 baseline **V1**（不执行 V1 里的语句，更不会 DROP）。
2. 然后只跑 **V2 及以后** 的增量脚本。
3. 增量脚本全部是加字段（MySQL 8.0 没有 `ADD COLUMN IF NOT EXISTS`，用 `information_schema` 判断后再 `ALTER`），**不 DROP 表、不 DROP 库**。

本任务增加的字段：

| 版本 | 内容 |
| ---- | ---- |
| V1 | 空基线（占位）。现网库由 baseline 标记，不执行 |
| V2 | `t_user.session_version`（禁用账号时加一，踢掉已登录会话） |
| V3 | `t_record.order_no` / `t_import_item.order_no`（订单号/商单号，查重用） |

当前 Docker `gjp-mysql` 为 MySQL **8.0.37**。不要用 MariaDB 的 `ADD COLUMN IF NOT EXISTS`。

手工对照（一般不必，启动应用即可）：

```bash
# 不要对已有库跑 schema.sql
docker exec -i gjp-mysql mysql -u root gjp < 运行包/migrate/V2__add_session_version.sql
docker exec -i gjp-mysql mysql -u root gjp < 运行包/migrate/V3__add_order_no.sql
```

旧的 `运行包/patch_import.sql` 仍可用于「只有流水表、还没有导入三张表」的更老库；有 Flyway 之后新字段走 `db/migration`。

## 对照

| 场景 | 用什么 |
| ---- | ------ |
| 空机器第一次装 | `schema.sql` + `data.sql`，再启动 jar（Flyway 会 baseline + 跑已包含在 schema 里的列则 IF NOT EXISTS 跳过） |
| 已有数据升级 | **只启动应用**，让 Flyway 跑 V2+；或手工跑 `运行包/migrate/V*.sql` |
| 已有数据 | **禁止** `schema.sql` / `data.sql` |
